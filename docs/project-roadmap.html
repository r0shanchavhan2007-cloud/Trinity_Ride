Trinity Ride — build route

A campus-only ridesharing app: student ID verification, QR-scan ride start, live maps, and fares set below market. Seven stops from idea to launch.

1

Foundations

1–2 weeksNo dependencies

Lock the decisions everything else builds on.

  • Define roles: Rider, Driver, Admin — a student can be both rider and driver
  • Fare model: base + per-km, priced 10% under your Pune auto/cab benchmark
  • Verification flow: college email domain, ID number, or admin-approved upload
2

Backend & database

2–3 weeks

The MySQL core and identity layer.

  • Schema: users, rides, vehicles, qr_codes, ride_requests, payments
  • Auth via college email OTP
  • Unique QR/code generation tied to each verified student
Needs → Phase 1 role & verification decisions
3

Maps & location

2–3 weeks · parallel

Nearby-driver matching and live routing.

  • Map provider decision — see hazard note on "free" maps
  • Geolocation radius search for nearby drivers
  • Route, ETA, and fare estimate
Needs → a location table ready in the backend
4

Frontend UI

3–4 weeks · parallel

Rapido-style screens, built against mocked data first.

  • Home map, pickup/drop pins, ride-type cards
  • Driver-en-route and ride-in-progress screens
  • Camera-based QR scan screen to start a ride
Needs → draft API contracts from Phases 2 & 3
5

Ride lifecycle logic

2 weeks

Wiring the pieces into one flow.

  • Request → match → scan-to-start → live tracking
  • Scan/confirm-to-end → fare calc → rating
Needs → Phases 2–4 integrated
6

Testing & pilot

2–3 weeks

Prove it on a small, real slice of campus.

  • Closed pilot — one department or hostel block
  • Load-test matching under concurrent requests
Needs → a merged, testable build
7

Launch & iterate

Ongoing

Wider campus rollout, feedback loop, monitoring — the line keeps going from here.

Hazards on the route

Worth deciding on early — each of these reshapes a phase above if left until later.

"Free" maps aren't free at scale

Google Maps' free tier ends fast under live tracking pings. OpenStreetMap + Leaflet is genuinely free but needs more routing work yourself.

Liability & safety

Real money, real rides, real students — talk to college administration before the pilot, not after.

QR spoofing

A static code tied to identity invites screenshot-and-reuse. Use short-lived or signed tokens instead.

Fare benchmark math

"10% cheaper" needs a maintained reference price — manual updates or fragile scraping, decide which.

Student data in MySQL

ID numbers, phone numbers, live location — hash sensitive fields, enforce HTTPS, restrict who can query what.

Scope vs. team size

Demo-ready in ~2–3 months with a small team; safe for real rides takes longer. Size the team against the route above.
